# Repo review — July 2026

A housekeeping pass over **map-context** (the Context Mapper / Tel Aviv
Atlas tool). Written in plain language; no application code was changed,
so nothing about how the tool runs is different.

## What I cleaned up

- **Added a README.** The repo had no front page at all — anyone landing
  here (including future you) had no way to know what the tool does or
  how to start it. There's now a `README.md` explaining what it is, the
  one-command way to run it (`npm start`), the other run modes, what
  each file is for, and a few "good to know" notes. It was written from
  the actual code and `ATLAS.md`, so it matches reality.
- **Moved the reference material into `docs/`.** The `REFERENCE_ux-ui`
  folder (43 screenshots plus two analysis documents about the ArchTools
  demo this project was inspired by) now lives at
  `docs/reference-ux-ui/`. Nothing in the code used it, so this is purely
  organizational: the repo root now contains only things the tool needs
  to run, plus the README.
- **Tightened `.gitignore`.** Added standard entries so log files and
  any future `.env` file (the usual place people put passwords/keys)
  can never be committed by accident. Grouped and commented the file so
  it's readable.

## What's in good shape

- **No secrets or API keys anywhere — I checked.** I searched every file
  for keys, tokens and passwords: nothing. All the data sources the tool
  talks to (OpenStreetMap, data.gov.il, GovMap, Tel Aviv GIS, elevation
  services) are free public services that need no credentials. That's a
  genuinely nice property — there is nothing here that can leak.
- **`ATLAS.md` is accurate.** I cross-checked it against the code: the
  commands, the port (3111), the cache behavior, and the tuning knobs it
  describes all match. No typos worth fixing, either.
- **Runtime clutter was already handled.** Generated files (`cache/`,
  `output/`) were already ignored by git, the dependency lockfile is
  committed, and the minimum Node version is declared. Good hygiene.
- **The code is tidy and well-signposted.** Clear section headers,
  helpful comments, and a built-in offline "mock" mode for testing the
  atlas without internet.

## Suggestions for the future

In priority order:

1. **If the repo is (or ever becomes) public, consider the address in
   `config.json`.** It contains a specific real street address in Neve
   Tzedek. It's not a secret and nothing bad happens automatically — but
   if that's a home or client address and the repo is visible to others,
   you may prefer a neutral example address there (e.g. "Rothschild
   Boulevard 1"). One-line change, zero risk to the tool.
2. **If you ever deploy the launcher publicly (e.g. Railway), know that
   its endpoints are open.** Anyone who finds the URL can trigger
   analyses on your server, and the way it's configured, other websites
   can call it too. There's no data at risk — the worst case is someone
   using up your server's time and the public map services' goodwill.
   Fine for a personal/demo deploy; if it becomes a shared tool, adding
   a simple access check would be a small, worthwhile job.
3. **The screenshot archive makes the repo heavy (~55 MB).** Even after
   moving it into `docs/`, git keeps every past version of those images,
   so every fresh download of the repo pulls all of it. If cloning ever
   feels slow, the fix is to keep the two analysis documents in the repo
   and park the screenshots in Drive/Notion with a link. (Truly shrinking
   the repo means rewriting git history — doable but delicate; only worth
   it if size actually bothers you.)
4. **A two-minute smoke test after changes.** There are no automated
   tests (normal for a tool like this). A good habit after any edit:
   run `npm run atlas:mock` (should finish without errors) and `npm
   start` once (dashboard should render for a known address). That
   catches most breakage.

## Things to watch out for

- **The government data sources are the fragile part.** The tool leans
  on several Israeli public APIs (data.gov.il, GovMap, land.gov.il,
  mavat.iplan.gov.il, Tel Aviv GIS). These occasionally change or go
  down without notice. If a dashboard section suddenly comes back empty,
  suspect the source before suspecting the code — try again later first.
- **Fair-use limits.** The free map services (Nominatim geocoding,
  Overpass) throttle heavy users. Normal use is fine; just avoid
  hammering many analyses in a tight loop.
- **Building heights are indicative.** Where official height data is
  missing, buildings get a plausible default — the fabric looks right
  but isn't surveyed. Don't base measurements on it (this is also noted
  in `ATLAS.md` and the README).
- **One path changed.** If you had bookmarks or notes pointing at
  `REFERENCE_ux-ui/`, that folder is now `docs/reference-ux-ui/`.
  Nothing in the code referenced the old path, so the tool itself is
  unaffected.
